keyjson-storage API

A simple JSON key-value store: one JSON document per name.

  • Quick start
  • Response format
  • GET: read value
  • POST: write value
  • Try it

Overview

A single endpoint handles both reading and writing. The base URL is wherever the docs/ folder is served (its index.php), for example:

https://your.api/endpoint

When running locally with php -S localhost:8000 -t docs, the base URL is http://localhost:8000/.

  • Each name stores one JSON value: an object, an array, a string, a number or a boolean.
  • Only names registered in config.php can be used (see Notes). The examples use tmp, the dev key that ships with secret 1234.
  • CORS is open to all origins (Access-Control-Allow-Origin: *), so you can call the API directly from a browser. The browser sends a preflight OPTIONS request before each JSON POST, and the API allows it.

Quick start

# write
curl -X POST 'https://your.api/endpoint' \
  -H 'Content-Type: application/json' \
  -d '{"name":"tmp","secret":"1234","value":{"hello":"world"}}'
# {"success":true,"message":null}

# read
curl 'https://your.api/endpoint?name=tmp'
# {"success":true,"message":null,"data":{"hello":"world"}}

Response format

Every response is JSON with this shape:

{
    "success": true | false,
    "message": null | "error message",
    "data": ...            // GET only, when success is true
}

The HTTP status is always 200, including for errors. Check success and message to see the result.

GET: read value

GET https://your.api/endpoint?name={name}[&key={key}]

Query parameters

NameTypeRequiredDescription
namestringyesKey to read
keystringnoReturn only this top-level property of the value (or this index, if the value is an array). This makes the response smaller.

Success response

{
    "success": true,
    "message": null,
    "data": [
        { "name": "Black", "code": "B" },
        { "name": "White", "code": "W" }
    ]
}

Errors

messageCause
name not foundname is missing or not registered on the server
data not foundThe name is registered but nothing has been written to it yet
key not foundkey is given but the value has no such property or index

Examples

curl

curl 'https://your.api/endpoint?name=tmp'

curl, one key only (returns "data": { "name": "Black", "code": "B" })

curl 'https://your.api/endpoint?name=tmp&key=0'

fetch

const resp = await fetch('https://your.api/endpoint?name=tmp').then(r => r.json());
console.log(resp.data);

jQuery

$.getJSON('https://your.api/endpoint?name=tmp', resp => console.log(resp));

POST: write value

POST https://your.api/endpoint

This creates the value if it doesn't exist, or replaces the whole value if it does. The request needs Content-Type: application/json.

Request body

FieldTypeRequiredDescription
namestringyesKey to write
secretstringyesThe write secret registered for this name
valueany JSONyesThe value to store (cannot be null)
{
    "name": "tmp",
    "secret": "1234",
    "value": [
        { "name": "Yellow", "code": "Y" },
        { "name": "Blue",   "code": "B" }
    ]
}

Success response

{
    "success": true,
    "message": null
}

Errors

messageCause
name not foundname is missing or not registered on the server
invalid inputvalue or secret is missing or null
invalid secretsecret doesn't match the one registered for this name

Examples

curl

curl -X POST 'https://your.api/endpoint' \
  -H 'Content-Type: application/json' \
  -d '{"name":"tmp","secret":"1234","value":[{"name":"Yellow","code":"Y"}]}'

fetch

const resp = await fetch('https://your.api/endpoint', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
        name: 'tmp',
        secret: '1234',
        value: [ { name: 'Yellow', code: 'Y' } ],
    }),
}).then(r => r.json());

jQuery

$.ajax({
    url: 'https://your.api/endpoint',
    type: 'POST',
    contentType: 'application/json',
    data: JSON.stringify({
        name: 'tmp',
        secret: '1234',
        value: [
            { name: 'Yellow', code: 'Y' },
            { name: 'Blue',   code: 'B' },
        ]
    }),
    success: resp => console.log(resp),
});

Notes

  • Reads are public. Anyone who knows a name can read its value without a secret. Don't store sensitive data.
  • Writes replace the whole value. There's no partial update or merge. To change one item, read the value, modify it, then write it all back.
  • Registering a name. Add the name and its secret to config.php on the server: 
    $config = [
  "tmp" => [
    "secret" => "1234",
  ],
];
